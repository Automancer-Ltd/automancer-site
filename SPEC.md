# Automancer Site — Living Specification

> Internal living spec. Update the relevant module section in the SAME branch
> as any behaviour change. Last verified against the code: 2026-11-22.

## North star

Provide a truthful public front door for Automancer. Give people and machines the same current facts. Keep the site fast, accessible, and free from visitor tracking.

## Key principles

- `VISION.md` is the highest authority in this repository.
- Publish only claims that have evidence in the Automancer truth layer.
- Generate human and machine surfaces from shared source data.
- Keep published machine identifiers stable.
- Publish service prices on the site.
- Do not add analytics, advertising cookies, accounts, sessions, or a site database.
- Keep prospect communication under human control.
- Test the static output that production serves.

## Module map

### Public pages

- Work opens with a case-study directory using the published sector labels. Every link opens its study directly, with the directory beside the introduction on wide screens and below it on narrow screens. It works without JavaScript.
- Field Notes opens on its newest note (t25360). Its hero shares Work's compact size (`.page-hero--compact` in `global.css`, used by both pages), the list starts closer under it, and below 48rem the subject buttons are one row that scrolls sideways (fading out where more follow; the page itself never scrolls sideways). The newest note's title and summary are on the first screen of a 390 × 844 phone and its title on a 1280 × 800 laptop, with scripts off. Arriving at `#topic-<slug>` also scrolls the picked button into the row's view. No words changed.
- An unknown path returns a real HTTP 404. Its main content offers Home and links to the five other primary destinations on the first phone and desktop screens. Direct email and voicemail follow, alongside the sitemap, plain-text guides and developer reference.
- At 820px and below, the header puts Contact one tap away. Menu opens a compact, native disclosure with a highlight for the current page or section. The links and toggle work with JavaScript disabled. With JavaScript, Escape returns focus to Menu, and moving focus outside or tapping outside closes the panel.
- Every page carries its compiled styles in its HTML so a first visit can paint without fetching a stylesheet. Astro adds the style hashes to each page's CSP. The build places the policy before the font preloads and inline styles. Fonts and scripts still use their cacheable asset URLs. While a web font loads, its text is drawn in an installed Arial or Courier New sized to it (`<family> Fallback` faces in `src/styles/fonts.css`, written by `ops/fonts/fallbacks.py`; t23013), limited to the web font's own characters, so lines wrap where they will in the web font and the settled page is unchanged. Android draws them in Roboto (`<family> Android Fallback`, t23067). The first thing in `<body>` is a hashed inline script that asks for every fallback face, because Firefox never starts one by itself while the web font is pending (t23138).
- Decorative CSS animations pause offscreen and resume when they return to view. They respect the visitor's reduced-motion setting. The effects that run while a visitor reads move only by transform and opacity, so the compositor runs them without the page's main thread (t21746): the spectrum glow (`SpectrumGlow.astro`) crossfades one static layer per colour, and the spectral rules, the home and developer heroes' fold line and the nav's current-page underline slide a strip inside a clipping host. Since t21966 the rest do too: every pulsing spectrum bead (`Bead.astro`: the hero eyebrow, `.sys--spectral` labels, the case-study `.live-dot`, the proof-strip dot) is a clipped sliding strip plus a ring that grows by scale and fades by opacity; the hero's spectral word (`.hero__headline .spectral-text`) clips a sliding strip to its glyphs with `mask-clip: text` (an inline-block, which WebKit needs); the service price's underline (`.offer__rule`) is a clipping host with the sliding strip. Still repainting where they show: the spectral phrases that can wrap (the footer tagline, the home page's "the same tools…"), which main.js pauses offscreen, and the hero word in Firefox, which lacks `mask-clip: text`.
- What it does: Serves the marketing, services, work, field notes, about, contact, privacy, terms, and recovery pages as static HTML. The services page opens with all four from-prices beside its introduction on desktop, stacking the comparison below it on phones. Each comparison row is a native link to its offer details; keyboard focus follows the link, and the target clears the fixed header. The home headline and service-price cards reflow on narrow screens with enlarged text: display amounts are bounded by their panel width, price rows wrap, and offer columns allow text to wrap inside the screen. Every page keeps its words on screen at 320px and with text at 200% (t21036): a word longer than its line breaks rather than being clipped by `body`'s hidden horizontal overflow, case-study figures sit in a wrapping row whose cells never get narrower than their longest word (and widen with enlarged text), a case study's status notes wrap below its sector when the column is narrow, and the /about/ headings, which never break inside a word, size to their column. The browser journey walks every sitemap page at 320px, 390px and 1280px, at normal and 200% text, and fails on any text painted outside the screen, a clipping ancestor or its panel. The footer proof strip publishes real build provenance only; it is not a live service-health indicator.

- What it does: Builds case studies and field notes from typed Markdown collections. It excludes drafts from production indexes, feeds, mirrors, and generated routes. The list repeats the page's headings, so `page-dates` leaves it out of the page's words and no page date moves.
- Keep reading (t22126): every field note ends with three other published notes, chosen by `relatedNotes` (`src/data/related-notes.ts`): the same topic label first, then the most tags in common (tags carried by more than a quarter of the notes do not count), ties to the newer note, so every note offers three. "General" names no subject, so it gets no button and its notes show under "All". Each field note's subject label in its header links to that address; the "General" note's does not. The build draws each card from SVG with resvg (WebAssembly, no browser) using static instances of the site's own fonts (`src/assets/og/`, cut from the served subsets by `ops/og-card/fonts.py`) and stops on a character those fonts lack. Every page's `og:image` is a built PNG whose size matches its `og:image:width`/`height` tags (`tests/og-cards.test.ts`); the journey fetches three cards (a note, a case study and /services/) from the origin under test, production included. Since t22092 every other page has one too, at `/og/pages/<name>.png` (`pageCards` in `src/data/share-cards.ts`; `BaseLayout` picks a page's card by its path, and the 404 page uses home's): the page's own eyebrow and h1, the spectral word drawn in the site's yellow-green-blue where the page has one (home's "oblivion", /developers/' "data"), and one fact the page shows (the response promise, the latest release, the number of notes or case studies, a legal page's last-updated date). Each page's WebPage JSON-LD carries its card as `primaryImageOfPage`. Tests hold that every hand-authored page names its own card, that its alt carries the page's h1, that only home and /services/ show the prices and show all four, and that `primaryImageOfPage` is the `og:image`. The hand-made generic `og-image.png` and its source `ops/og-image/` are gone.

Each such figure gets a "Source ↓" link to its row under "Where these numbers come from" after the case study's body, which quotes each claim's `sourceQuote` word for word (emphasis removed, a shared line once) and names the private case-study dossier it comes from; the Markdown twin ends with the same section, and `/api/case-studies.json` lists each figure's `claims` ids. ### Machine-readable surface

- A client can ask for Markdown at the page URL or the direct `.md` URL (t24736). Both use the build's Brotli copy when the client accepts it. Both revalidate the selected copy with `If-None-Match` or `If-Modified-Since`; an unchanged twin returns `304` with no body. The page URL keeps the twin's `Content-Location` and varies by media type and encoding. Pages without a twin still serve HTML, and missing pages can still return a Markdown `404`.
- Case-study citations (t23813). `/llms.txt` links the figures in its recommendations to their evidence rows using the URLs in `/api/claims.json`. `/llms-full.txt` and the case-study Markdown twins share the headline figures, links and quoted evidence. Both the full guide and the twins give evidence links as absolute URLs so a saved copy can still lead a reader to the source.
- Field note subjects (t22833): `/api/field-notes.json` publishes a `topics` array with each filter's `label`, `slug`, `count`, absolute `url` and `noteSlugs` in newest-first order. An agent can look up the matching notes by slug or share the URL to open the matching browser filter. The Markdown twin and `llms.txt` list the same subjects, counts and links. The twin also gives each note's subject and direct Markdown link in the full list. `General` notes remain in that list. The build audit compares the machine formats with the published index.
- What it does: Publishes Markdown twins, JSON endpoints, OpenAPI, JSON-LD, feeds, `llms.txt`, an agent manifest, a sitemap, security contact data, and the stability policy below. An edge Worker serves a page's Markdown twin to `Accept: text/markdown`, a Markdown 404 to agents that ask for one, RFC 9457 errors under `/api/`, RFC 8288 `Link` headers, and a single 301 from each legacy `*.html` URL to its page (GitHub Pages alone serves a 301 to `/x.html/` and then a meta-refresh stub); `/.well-known/` carries an ARD manifest and an RFC 9727 API catalog. Legal page bodies remain canonical in HTML and are not copied into machine-readable mirrors. Every page in `/api/pages.json` and the sitemap carries a real date: `lastModified` / `<lastmod>` is when the words on the page last changed on the live site, with `contentSha256`, the hash of those words; the deploy carries forward the date production publishes for unchanged words, so a deploy that changes no words changes no date (t19631).

- The edge Worker serves complete HTML for byte-range requests (t25022). Removing the Pages lock changes the offsets, so only direct file downloads that can be served byte-for-byte honor ranges. The local Pages stand-in answers single-range requests, and the visitor journey checks complete HTML and partial PNG downloads before and after deployment.

### Browser script protection

- What it does: Astro generates a Content Security Policy in each HTML page, including the recovery page, and a build hook stamps the same `default-src 'none'` and Trusted Types floor onto every legacy redirect stub (`dist/*.html/index.html`) so all 37 emitted HTML files carry a policy (t22166). Approved inline scripts get build-time hashes; external scripts load only from the site's own origin or Cloudflare Turnstile. Unapproved inline scripts, event-handler attributes and eval are blocked. Inline style attributes remain allowed for the existing layout and animations; style elements require a hash or same-origin source. Everything else starts from nothing (`default-src 'none'`): images, fonts, the manifest, form targets and base URLs come only from the site itself, and a page may send data (`connect-src`) only to its own origin and the error-report origin of the Sentry DSN the build bundles. `/contact/` alone adds the enquiry API and Turnstile's frame. So the browser itself refuses any request to an analytics, advertising or other third-party host, even from code the policy lets run (t21404). Trusted Types is on for every page: the browser refuses any plain string written into an HTML or script sink (`innerHTML`, `insertAdjacentHTML`, a script's `src`, `on*` attributes, string eval and the rest), and no page may create a policy except `/contact/`'s `turnstile` loader, which yields only Turnstile's exact script URL (t21659). The edge Worker's policy restricts framing, base URLs and objects on every response, upgrades SVG and XML responses (`image/svg+xml`, `application/xml`, which carry no `<meta>` tag) to `default-src 'none'` plus Trusted Types, and 301-redirects every legacy `.html` path variant (including `/<name>.html/index.html` and `//<name>.html/`) at the edge before touching the origin (t22166). Every response also carries `Cross-Origin-Opener-Policy: same-origin`, so a site that opens a page in a window gets back a closed handle and cannot later send that window to a look-alike page, message it or count its frames; and no response carries `NEL`, `Report-To` or `Reporting-Endpoints`, which would have the visitor's browser post reports to a server for days after the visit, outside the page CSP. Cloudflare's zone setting `nel` added the first two to every response until t22383; it is off on both zones, and the Worker strips any the origin adds. `ops/verify-production.sh` reads back the served page CSP, Trusted Types and `connect-src` DSN-origin match, plus the SVG/XML CSP and legacy 301s, and fails if a page, twin or 404 sends a reporting header, on every deploy. This is defence in depth, not a claim that the site had an exploitable injection path.
- State: built
- Shaped by: `astro.config.mjs`, `src/layouts/BaseLayout.astro` (`trustedTypes`), `src/pages/contact.astro`, `src/components/InlineScript.astro` (hashes trusted template scripts, including `define:vars`, through Astro's CSP API), `ops/edge/worker.js`, `ops/verify-production.sh`, `tests/csp.test.ts`, `tests/edge-worker.test.ts`, `tests/journey/security.spec.ts`, and `tests/journey/visitor.spec.ts`.

### Runtime health signals

- What it does: Reports production browser errors to the configured Sentry project, tagged with the deployed commit as the release. The browser sends standard error types, the page's built canonical path and known first-party script locations with line and column numbers. It excludes raw exception text, rejected objects, stack function names, activity history and arbitrary URLs. The Sentry SDK sends only error events and is fetched only when the first error happens, so a visit with no error never downloads it. It posts them to this site (`/_errors`), and the edge Worker passes them on to the Sentry project without the visitor's IP address, so a page talks to no third party and the Worker refuses reports from other sites or for other projects (t24432). The Worker signs each report with a key only it holds (the Worker secret `SENTRY_KEY`) and takes about ten a minute from one address; the DSN in the page holds no key Sentry takes, so nobody can post into the project directly (t24883). On the Sentry side (`automancer-site`), `allowedDomains` is locked to `automancer.uk` so Relay filters out cross-origin browser events from any other origin (`reason: cors`), server-side JavaScript scraping is disabled (`scrapeJavaScript: false`, `verifySSL: true`), and replay and performance loader flags on the public client key are off (t22166; per-key rate limits are a Sentry Business-plan feature, so `rateLimit` remains null under Spike Protection on `am3_team`). Private vulnerability reporting is enabled on the public GitHub repository (`t22166`). UptimeRobot independently checks public URL availability. The production verifier checks every published page and Markdown twin, the served page CSP and SVG/XML/stub edge protections, the machine surfaces and TLS after every deploy. Estate-watch's `siteVerify` schedule runs its checks every 30 minutes and files a Gandalf task on failure.
